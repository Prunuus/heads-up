# v3 results: the CFR blueprint (Track B)

## Task 17: training deal dataset (`train/gen_deals.py`)

- Machine: AMD Ryzen 7 9700X (8 cores / 16 threads), 15 GB RAM, WSL2 Ubuntu 24.04, Python 3.12.3, numpy 2.5.4.
- Every run was pinned to logical CPUs 8-15 at `nice -n 19`, because Track A was running timing work on CPUs 0-7 (ruling R32). CPUs 8-15 are 4 physical cores with SMT.

### Throughput

Wall time includes Pool start-up; `--shard-size 5000`.

| workers | deals | wall | deals/s | per worker |
|---|---|---|---|---|
| 1 | 10,000 | 12.5 s | 803 | 803 |
| 4 | 40,000 | 14.2 s | 2,823 | 706 |
| 8 | 80,000 | 21.3 s | 3,757 | 470 (two per physical core) |

- A deal costs about 1.25 ms of one core. That is 8 feature calls (2 preflop, 6 postflop) through `bot.abstraction`, plus 2 `evaluator.omaha_score` calls at about 30 µs each.
- SMT adds about 33% over one worker per physical core.

### Acceptance run: 2,000,000 deals

    taskset -c 8-15 nice -n 19 python -m train.gen_deals --n 2_000_000 --workers 8 --iters 1000

- Wall: 510.9 s (3,916 deals/s). User CPU 3,980 s; GNU time's max RSS was 127 MB.
- Output: `train_data/` (git-ignored), 40 shards of 50,000 deals, 6.6 MB each, 264 MB in all (132 bytes a deal).
- Dataset: seed 0, bucket counts 200/100/100/100 (`data/buckets.npz` at cf30916), numpy 2.5.4.

Checks on the finished dataset:

| check | result |
|---|---|
| 2,000 random deals: 8 buckets each vs `bot.abstraction.bucket()`, showdown vs `evaluator.omaha_score` | 0 mismatches |
| vectorized `buckets_from_features` on all 2M rows vs the stored buckets | identical (0.78 s) |
| deals with a repeated card | 0; card ids 0..35 |
| showdown: button wins / split / big blind wins | 47.81% / 4.45% / 47.74% |
| bucket occupancy (min to max vs uniform), preflop / flop / turn / river | 0.83-1.22 / 0.92-1.09 / 0.93-1.05 / 0.55-1.85 |

The river spread is the nut buckets, as Task 16 measured (0.58-1.97).

### Loading and re-bucketing

- `load_deals("train_data")`: 0.05-0.07 s from a warm page cache.
  - Buckets and showdown take 34 MB of arrays (17 bytes a deal); peak RSS is 67 MB, of which 33 MB is the interpreter and imports.
  - With `cards=True`: 0.09 s, 96 MB. With `features=True` as well: 0.19 s, 291 MB.
- `--rebucket` of the 2M against a 400/200/200/200 refit (same designs, seed 0) took 2.2 s. Going back to `data/buckets.npz` took 5.0 s.
  - Both are bound by disk writes; the CPU work is 0.8 s per million deals.
  - The round trip gave back bit-identical buckets.
  - 500 random deals matched the refit's `bucket()` on their cards with 0 mismatches.
  - While the dataset was on the refit, `load_deals` refused the default table.
- Why the features are stored as float64: rounding them through float32 would have moved 0.25% of the flop buckets and 0.13% of the turn buckets of these 2M deals. Preflop and river are unaffected.

### Projection to the 20M target

- Generation: about 85 min pinned to CPUs 8-15 (8 workers), or about 45 min on all 16 CPUs of an idle PC.
- Disk: 2.6 GB.
- `load_deals`: about 0.6 s warm, 340 MB of arrays.
- Re-bucketing: 20-50 s.
